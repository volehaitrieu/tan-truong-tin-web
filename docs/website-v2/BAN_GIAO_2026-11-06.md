## 3. VIỆC DỞ #1: Nhập Excel đọc cột Tồn (nhánh `feature/nhap-excel-ton-kho`)
Quyết định chủ shop (06/11): với SP ĐÃ CÓ, số Tồn trong file = tồn MỚI (đặt đúng số), hiện "tồn cũ → tồn mới" ở bảng "Thay đổi chờ xác nhận" để tick; ô Tồn trống = giữ nguyên; mỗi lần đổi ghi vào lịch sử nhập kho. SP mới: tồn đầu kỳ = số trong file (lý do "Nhập hàng"). Làm RIÊNG từ nhánh `main` rồi chủ shop tự deploy (không kèm giao diện v2).
Cách làm: đặt tồn qua hàm DB `adjust_stock(p_product_id, p_delta, p_reason, p_note)` (SECURITY DEFINER, đòi quyền `adjust_stock`, lý do hợp lệ: 'Nhập hàng','Hư hỏng','Thất lạc','Trả hàng','Kiểm kho','Khác'; |delta| ≤ 100000; không cho tồn âm). KHÔNG ghi thẳng bảng `inventory`.
### Đã sửa trong nhánh
- `lib/excel/parse-products.ts`: thêm `MAX_STOCK`, cột "Tồn" vào `TEMPLATE_COLUMNS` (sau "Vị trí"), `ImportRow.qty`, đọc `qty` ở mẫu chuẩn, kiểm lỗi trong `finish()`.
- `app/admin/(shell)/nhap-excel/actions.ts`: `setStock()`, `canStock`, ghi tồn cho SP mới, so sánh `qty` cho SP đã có (đưa vào `import_changes`), áp tồn trong `applyChanges`, kết quả có `stockSet/stockFailed/stockIgnored`.
### CHƯA làm (theo thứ tự)
1. `app/admin/(shell)/nhap-excel/ReviewTable.tsx`: thêm `qty: "Tồn kho (đặt đúng số này)"` vào `LABEL`.
2. `app/admin/(shell)/nhap-excel/ImportClient.tsx`: `WIDTHS` thêm 1 phần tử (rộng 8) sau cột Vị trí; 2 dòng ví dụ trong `downloadTemplate` thêm giá trị Tồn TRƯỚC Tồn tối thiểu (hiện thiếu → lệch cột); sheet hướng dẫn thêm dòng "Tồn: số hàng đang có, ô trống = giữ nguyên; cần quyền chỉnh tồn"; `downloadErrors` thêm key "Tồn": `r.qty`; bảng xem trước thêm cột "Tồn"; sửa câu "Số tồn không thay đổi." ở dưới bảng; thông báo kết quả thêm `stockSet`, `stockFailed`, `stockIgnored`.
3. `lib/admin/product-export.ts`: bỏ "Tồn kho" khỏi `EXTRA_COLUMNS`, thêm khóa "Tồn": `r.inventory?.qty ?? 0` vào map `cells` (đang lỗi kiểu vì `TEMPLATE_COLUMNS` đã có "Tồn").
4. Tạo `supabase/migrations/20261106000100_import_changes_qty.sql` (xem SQL dưới). Chỉ ghi tệp; KHÔNG chạy trước khi chủ shop đồng ý.
5. Kiểm: `npx tsc --noEmit`, `npx eslint`, `npm run build`; thử bộ đọc bằng 2 file xuất ở `exports/` (cần cột Tồn đọc đúng = 5); thử `detectAndParse` với file DMHH/quạt cũ vẫn chạy.
6. Chủ shop đồng ý → chạy migration TRƯỚC (an toàn vì tương thích ngược), rồi mới deploy mã. Dùng công cụ Supabase `apply_migration`, ghi lại phiên bản (version) do hệ thống trả về và ĐỔI TÊN tệp migration trong repo cho khớp (lịch sử migration Supabase ↔ repo từng bị lệch). Deploy: chủ shop tự chạy `npx vercel deploy --prod --yes` trong Terminal (công cụ AI bị chặn deploy production).
SQL migration cần có:
```sql
alter table public.import_changes drop constraint import_changes_field_check;
alter table public.import_changes add constraint import_changes_field_check
  check (field = any (array['name','unit','price','import_price','category','industry','brand','location','min_qty','qty','spec','description','warranty','origin','made_in']));
```
Rủi ro đã biết: tính chênh lệch theo tồn lúc bấm xác nhận (không theo lúc nhập file); nếu có bán hàng cùng lúc, tồn có thể lệch vài đơn vị — chấp nhận, ghi rõ.
